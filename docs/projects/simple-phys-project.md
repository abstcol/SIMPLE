# SIMPLE-Phys 项目定义与实施计划

> 工作名称：SIMPLE-Phys（暂定，非官方项目名称）
> 需求确认日期：2026-11-10
> 状态：需求已确认；任务、模型和 WBC 兼容性核查待开展；PHYS 功能尚未实现。
> 本文区分已确认约束、实施建议和待核实事项。建议不等于实验已完成或范围已承诺。

## 1. 项目目标

基于 SIMPLE 建立一个研究型人形机器人**仿真物理鲁棒性 benchmark**，研究物体质量、质心及操作接触变化如何影响抓取、弯腰取放、持物移动和全身稳定性。

第一投稿目标为 IROS 2027 正式论文，交付完整实验、论文与补充材料；必要时收缩任务和模型数量，保留评测可信度。IEEE RAS 在需求确认日列出的论文截止日期为 **2027-03-01**，具体时间、时区及后续调整以官方通知为准，不预设延期。

核心研究问题：

1. 固定底层控制器时，操作物体的物理变化如何影响任务成功和身体平衡？
2. 哪些条件主要导致抓取滑落、动作跟踪不足或平衡失稳？上层策略与参考执行的差异能提供哪些诊断证据？
3. 静态操作和持物移动的失效边界有何不同？负载与接触因素是否存在显著交互？

论文贡献定位为评测协议、可复现实例集和分层失效分析。当前不承诺新训练方法，不把成功率下降直接解释为模型缺乏物理理解，也不把单个 WBC 内的诊断解释为跨控制器因果结论。

### 2.1 首版不包含

- 实机实验、策略训练/微调、WBC 重训或跨 WBC 泛化结论。
- 执行中改变质量/摩擦、突发外力等动态扰动。
- 脚底摩擦随机化、机器人本体阻尼/执行器能力随机化。
- 为扩充因素数目而加入尺寸、恢复系数、桌面倾斜或相机变化。
- 将通用开源权重默认视为可直接执行人形任务的有效模型。

后续扩大范围需要明确更新本文、资源需求和对应验收项。

## 4. 最小论文版本建议（尚待兼容性核查）

建议以 **3 个代表任务＋2 个现成学习策略＋1 套专家诊断基线** 为起点，属于规模目标，不是已经确认可运行的清单。

| 类别 | 候选方向 | 验收重点 |
| --- | --- | --- |
| 原地抓取 | `G1WholebodyTabletopGraspMP-v0` | 接触与抓取稳定性、负载对站立的影响 |
| 弯腰取放 | 已跑通的 BendPick 作为入口，再核查 `G1WholebodyPickAndBendPlaceMP-v0` 等完整取放任务 | 姿态变化、持续持物和放置稳定性；不能把只有抓取称为完整取放 |
| 持物移动 | 核查已有移动搬运任务与选定 WBC 的兼容性 | 持物行走、身体稳定和到达/放置成功 |

移动任务的具体环境 ID 待定，不能因为某任务存在于注册表，就假定它可与同一种 WBC、同一动作接口直接组合。若现成任务无法满足一致性，需要评估有限适配的工作量，而不是静默混用控制器。

模型筛选至少核查：实际 checkpoint、机器人与手型、任务覆盖、观测和动作语义、控制频率、WBC 兼容性、渲染域、推理依赖、许可和标称成功表现。模型不能依靠新训练解决兼容性问题；若只有一个有效模型，应重新评估比较范围与论文主张。

## 5. 评测协议

### 5.1 主集与压力测试

主集在每个采样条件下，由专家配合固定 WBC 完成执行验证后建立。验证必须在该物理条件下运行，不能沿用标称条件下的成功标签。

压力测试保存物理合理、数值有效，但在预先限定的专家尝试预算内未通过执行验证的条件。专家失败标记为“未验证可执行”，不标记为“物理无解”。穿透、非法惯量或数值发散等配置错误单独归档，不混入压力测试作为模型失败。

主集和压力测试分别报告结果。记录总采样数、有效条件数、专家接受率、尝试预算及拒绝原因。实例划分与筛选规则须在候选模型评测前冻结；不得根据被测模型结果调整测试集。模型分数不得反向用于选择参数范围。

### 5.2 物理因素设计

先做质量、质心、两类摩擦的单因素扫描，再做少量有解释价值的组合，优先研究负载与抓取摩擦的交互。数值范围通过开发集校准，按任务和资产约束确定，不直接照搬 RoboTwin-Phys 全局范围。

物理条件使用独立随机流。固定场景与物理条件的完整记录，不仅保存 seed；保存采样目标值、编译后实际值，以及接触中真正使用的参数。每次 reset 从标称配置恢复，避免随机倍率逐次累乘。

几何与质心不能混为一谈：首版改变质量分布，不改变可见外形和抓取几何。质心与惯量应对应可实现的质量分布。质量倍率应用时必须保持惯量更新一致。

### 5.3 视觉与输入

MuJoCo 阶段以物理机制和控制诊断为目的。论文视觉评测按已确认路线接入 Isaac，固定视觉条件的成对物理实验优先于扩展视觉随机化。

推荐保留四种配置接口：标称条件、视觉/布局变化、仅物理变化、联合变化。完整视觉矩阵是否纳入首版正式实验，待模型与 RTX 可用性核查后决定；物理对照不得混淆渲染域变化。

所有主评测策略使用预先约定的可观测输入。物理标签、专家轨迹、物体真实位姿等诊断信息不自动进入模型输入。真值输入对照必须单列，且说明接口与已有模型能力；单纯附加数值不构成有效对照。

### 5.4 指标与归因

建议同时报告原任务成功率和操作—平衡联合成功率；若后者增加持物时间、身体稳定性或放置条件，应明确新定义并冻结版本，不冒充官方成功率。

诊断指标包括：持续抬升/放置、滑落与接触持续时间、跌倒或倾斜、轨迹跟踪误差、力矩饱和时间、完成时间。不同失败可同时发生，不能强制互斥分类。

专家重新规划、固定参考动作执行和学习策略闭环执行分别统计。参考动作在变化条件下失败只能说明该执行方案不鲁棒；不能据此直接证明策略无解或单独归因于 WBC。

同场景配对比较，报告样本数、置信区间、单因素曲线及组合效应。正式 episode 数量由 pilot 方差、统计精度和实测耗时确定，尚未冻结。必要时对边界条件重复执行以测量随机性。

## 6. 工程落点与验收

现有入口：

- [DR 管理器](../../src/simple/dr/manager.py)、[物理 DR 占位模块](../../src/simple/dr/physics.py)。
- [Task 场景序列化](../../src/simple/core/task.py)。
- [MuJoCo 场景构建](../../src/simple/engines/mujoco.py)、[G1 AMO 控制](../../src/simple/robots/g1_wholebody.py)。
- [评测 CLI](../../src/simple/cli/eval.py)、[LeRobot 记录器](../../src/simple/envs/lerobot.py)。
- [既有复现说明](../../scripts/reproduction/README.md)。

拟增加独立物理条件配置和记录，尽量保持任务 ID、策略观测与动作接口兼容。默认关闭 PHYS 时须恢复冻结的标称版本行为。

实施顺序建议：

1. **先核查并跑通 Psi0＋SONIC 的现成权重与标称任务，确认无需训练。** 首个候选为 `G1WholebodyXMoveBendCarryBoxSonic-v0`，先验证权重严格加载、SONIC 回放与 Psi0 闭环，再决定 PHYS 改造切入点。
2. 定义物理参数 schema、作用对象、单位、独立 RNG 和版本字段。
3. 在场景构建/编译阶段应用参数，完成初始化、稳定性检查和实际值审计。
4. 加入指标、专家筛选、实例清单与分开的评测输出。
5. 对接视觉策略，冻结协议，开展正式对照实验。

关键验收项：

- 质量与惯量一致；非目标物体、脚—地条件和机器人参数不被误改。
- 手—物、物—支撑面摩擦确实作用于实际接触。当前桌面 `priority=10` 可覆盖物体摩擦，必须处理接触合成语义，不能只看配置值。
- 相同配置恢复到相同参数和初始条件；不承诺 GPU 规划或完整轨迹逐位一致。
- 冻结 WBC 的版本、权重、增益和动作适配；避免跨任务悄悄改变控制设置。
- 采样、拒绝、规划与执行的失败记录完整；可区分实现错误与策略失败。
- 模型输入不泄露物理真值；主集及压力测试版本可追溯。

## 7. 里程碑与资源

以下为按需求确认日倒排的建议节奏，尚不构成工期保证。用户每周约 20 小时；Codex 负责协助实现与核查，不能按另一名全职研究人员计算可用人工。

| 阶段 | 时间预算 | 交付与退出条件 |
| --- | --- | --- |
| M0 可用性核查 | 前 2 周 | 任务—模型—WBC 矩阵；确认移动任务、有效 checkpoint、标称基线和 RTX 依赖 |
| M1 物理原型 | 第 3–6 周 | 参数生效测试、配置恢复、诊断指标、范围校准；已有任务可复现 |
| M2 主实验 | 第 7–11 周 | 冻结协议与实例集，完成主要模型对照；如资源不足优先缩小数量 |
| M3 投稿准备 | 最后约 5 周 | 关键补实验、统计分析、论文、视频、复现说明与补充材料 |

正式实验和写作应交错推进；预留审阅与失败恢复时间，不把截稿日前最后一天作为实验完成时间。RTX 资源不作为 M0/M1 前提，但论文版 Isaac 路线存在明确资源依赖；如不能及时满足，应显式重评范围，不静默改成另一视觉协议。

### 7.1 风险与应对

| 风险 | 应对 |
| --- | --- |
| 专家在标称条件下仍不稳定 | M0 优先定位；固定尝试预算；缩小到已稳定任务，不能用成功回放替代稳定专家证明 |
| 找不到两个无需训练的有效模型 | 尽早核查 checkpoint 和任务匹配；如不足，重评比较规模和论文主张 |
| 持物移动需要另一套控制接口 | 先确认固定 WBC 可覆盖；不为凑任务数混用控制器 |
| 参数变化被接触优先级或强反馈掩盖 | 使用实际接触与执行指标验证；保留“影响小”的结果，不为显著下降而事后调范围 |
| 主集筛选偏向容易条件 | 预注册筛选规则、报告接受率，保留独立压力测试 |
| 参数导致数值问题或不合理质量分布 | 先做约束检查与最小物理测试；实现错误单列 |
| RTX 未到位或视觉域不匹配 | 早期确认资源；各渲染域分别建立标称基线，避免混合归因 |
| 截稿前资源不足 | 优先保留三类能力、有效对照与统计可信度，减少任务/模型数量 |

## 8. 交付物与协作规则

必需交付：物理条件配置与实现、版本化评测实例和筛选记录、诊断与统计工具、现成模型适配说明、可复现运行文档、论文主实验及补充材料。是否公开完整数据、公开时间与发布许可另行确认，不在此预先授权发布。

代码与配置通过本地特性分支、GitHub PR、服务器验证、验证后合并、两端同步主分支推进。文档修改做相应静态检查；物理或控制行为修改必须有相应实测，不用历史结果替代新提交验证。

沿用现有项目根目录。机器地址、端口、绝对路径等运行信息以实际环境为准，保存在本地配置或忽略的环境文件中，不将易变机器状态作为项目文档常量。依赖、权重、数据与成果留在既有持久项目目录；临时缓存不得成为重要成果的唯一副本。默认不做系统级安装或改动全局环境。

下一项工作是 M0 的 Psi0＋SONIC 标称链路核查，详见 [验证记录](../../scripts/reproduction/psi0-sonic.md)。公开任务 checkpoint 的存在不代表已经跑通；须分别记录权重加载、单步推理、动作回放和闭环任务结果。MuJoCo 渲染结果与官方 Isaac 视觉域分开报告。最终任务集合、WBC 冻结版本、参数范围、正式样本量和失败阈值仍待核实。
